# P0-11 CMM Sync + Outbox

P0-11 publishes orchestrator-owned execution facts to an external CMM through
an outbox. The CMM service and its TBD-03 wire protocol remain outside this
repository. `CMMPort` exposes only `get_view(context_id)` and
`append_event(ContextEvent)`; adapters do not invent remote fields.

## ContextEvent

The ten schema event types are:

`WORKFLOW_VERSION_CREATED`, `WORKFLOW_SELF_TESTED`, `EXECUTION_STARTED`,
`NODE_STATE_CHANGED`, `NODE_EVALUATED`, `ARTIFACT_REGISTERED`,
`CHECKPOINT_CREATED`, `WORKFLOW_REPAIR_APPLIED`, `WORKFLOW_COMPLETED`, and
`MEMORY_SUMMARY_UPDATED`.

`event_id` is deterministic over tenant, workflow identity, execution/node
identity and canonical payload. Payload validation rejects Secrets and
evaluator-owned fields recursively. P2 summary compression is not implemented;
`MEMORY_SUMMARY_UPDATED` is a schema/seam event only.

## Outbox and Publisher

The local `cmm_context_event` and `cmm_outbox` rows are written in one database
transaction. A unique event/idempotency key prevents duplicate logical events.
Publisher claims rows with a lease, calls `append_event`, marks `SENT`, or
returns a failed row to `PENDING`. Expired leases are recoverable after a
process crash. `cmm_outbox_lag` is emitted from the pending oldest timestamp.

## CMM Degraded Mode

`get_view` truncates returned context text to 24,000 characters. CMM connection
failure returns an empty degraded view and does not bypass Self-Test or any
release gate. Existing execution facts and pending outbox rows remain durable.

## Fact Source Boundary

`ContextEventBridge` provides explicit seams for P0-03 state transitions,
P0-07 Self-Test, P0-08 execution/attempt facts and P0-10 runtime reconciliation.
`NODE_EVALUATED`, `ARTIFACT_REGISTERED`, and `CHECKPOINT_CREATED` have schema
and seam definitions only; they have no real P1 source in this phase.

## Boundaries

No CMM server, TBD-03 formal protocol fields, P2 memory-summary compression,
or P1 recovery/evaluation implementation is included.
