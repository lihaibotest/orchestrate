# P0-07 Self-Test / Release Gate

## Scope

P0-07 implements an auditable S0-S4 pre-publication controller. It does not
implement the P0-08 execution controller, P0-09 Artifact manager, P0-10 runtime
event reconciliation, or a real repair-generating AI.

## Stage Matrix

| Stage | Validation | Dependency | Failure behavior |
|---|---|---|---|
| S0 | IR version, serialization, DAG, references, Binding structure, security | P0-05 validator | S1-S4 `SKIPPED` |
| S1 | Binding and frozen Snapshot identity plus lightweight reachability evidence | `AgentBindingProbePort` | S2-S4 `SKIPPED` |
| S2 | engine validate, inactive import, trigger preflight | P0-06 `WorkflowEnginePort` | S3-S4 `SKIPPED` |
| S3 | isolated Canary invocation, contracts, Credential Ref policy, Artifact write path | `CanaryProbePort`, `ArtifactProbePort` | S4 `SKIPPED` |
| S4 | readable status/node result, completion, monitoring evidence, terminal signal | `ObservabilityProbePort` | Workflow `SELF_TEST_FAILED` |

Only S0-S4 `PASS` transitions a Workflow Version to `VERIFIED`.

## Release Gates

Publish reserves a database record only when the locked Workflow Version is
`VERIFIED` and its latest successful Self-Test contains S0-S4 `PASS` with the
same IR hash, compiled workflow hash, and Registry Snapshot. Completion changes
the Workflow Version to `PUBLISHED` in the same transaction as the publish
record. Repeating the same completed publication is idempotent.

Formal execute requires both `PUBLISHED` and a completed matching publish
record. Self-Test Canary execution uses separate Ports and always carries the
`SELF_TEST` mode; it cannot open the formal execution gate.

## Retry And Repair

`SELF_TEST_FAILED -> SELF_TESTING` is legal only through the explicit Self-Test
repository path. An unchanged transient retry increments `repair_attempt` and
starts again at S0. A semantic repair creates an immutable child Workflow
Version with `parent_version`, repair reason, and failure signature before it
restarts at S0. `ORCHESTRATOR_SELF_TEST_MAX_REPAIR_ATTEMPTS` configures the
limit; exceeding it records `REPAIR_LIMIT_EXCEEDED`.

Failure signatures use SHA-256 over canonical stable fields: stage, error code,
rule, node, Agent, and normalized error class. Timestamps, trace IDs, UUIDs, and
free-form messages are excluded.

## Persistence

Migration `0004_self_test_release_gate` extends `self_test_run` and adds
`self_test_stage_result`, `workflow_repair_record`, and
`workflow_publish_record`. A partial unique index permits only one `RUNNING`
Self-Test for a Workflow Version. Evidence stored in PostgreSQL is limited to
metadata, references, hashes, and summaries.
