# P0-05 Execution IR and Deterministic Validator

P0-05 defines `execution-ir.v1` as the platform-neutral contract between Task
Plan processing and a future Workflow Compiler. The frozen Domain model covers
nodes, DAG edges, Snapshot-derived Agent Bindings, I/O contracts, Artifact and
Checkpoint metadata, recovery metadata, policies, and completion criteria. It
contains no Workflow Engine identifiers, engine-specific node types, credential
values, HTTP payloads, or external SDK dependencies.

`ExecutionIRValidator` implements the source-design rules:

- `IR-DAG-001/002`: unique references, dependency/edge consistency, no cycles.
- `IR-BIND-001/002`: required invocation Binding and exact frozen Snapshot match.
- `IR-SCHEMA-001`: valid contract structure and conservative edge compatibility.
- `IR-ART-001`: valid references and complete reusable Artifact evidence.
- `IR-REC-001`: valid Checkpoint/recovery references and Resume Root coverage.
- `IR-SEC-001`: Credential Ref only; plaintext credential material is rejected.

Validation issues are sorted and deterministic. A valid IR receives a SHA-256
hash over canonical JSON; invalid IR never receives a validated hash from the
Application Service. The service loads the P0-04 immutable Registry Snapshot
through its repository Port. P0-05 does not compile n8n JSON.

Run the full gate with Python 3.10 and PostgreSQL:

```bash
ORCHESTRATOR_DATABASE_PATH=/tmp/p005-foundation.sqlite3 \
P0_05_PYTHON_BIN=/path/to/python3.10 \
P0_05_POSTGRES_DSN='postgresql://user:password@host/database' \
bash scripts/check-p0-05.sh
```
