# P0-09 Artifact / MinIO Manager + WHOLE_ARTIFACT Handoff

## Scope

P0-09 closes the trusted Artifact path from successful Agent output to a
downstream-ready Task. Runtime event ingestion/reconciliation remains P0-10.
Trusted Checkpoint, input fingerprint, recovery lineage, FIELD_MAPPING, quality
scoring, reuse decisions, and invalidation remain P1.

## Artifact Model

`ArtifactIdentity` is the authoritative metadata model. It records Artifact
type, media type, schema reference, SHA-256, size, opaque storage reference,
tenant/Workflow/Execution identity, producer Node/Attempt, output name,
lifecycle, validation status, safe metadata, and creation time. Object content
never enters PostgreSQL or `ArtifactRef`.

`ArtifactRef` carries only Artifact identity, storage reference, hash, producer
identity, validation status, media/schema metadata, and size. The legacy P0-02
constructor remains an adapter-compatible form of this same model; no second
Artifact model was introduced.

Lifecycle is `CREATED -> VALIDATING -> VALIDATED -> CONSUMED`. Validation
failure enters `INVALID`; explicit deletion enters `DELETED`. Only PASS
Artifacts in `VALIDATED` or `CONSUMED` state can be bound downstream.

## Artifact Manager and MinIO Adapter

Application code depends on `ArtifactManagerPort` for put, metadata get,
existence check, validation, consumption, and delete. `MinioArtifactAdapter` is
the only MinIO SDK boundary. It accepts an injected client for deterministic
tests and provides `connect()` for production MinIO configuration.

The stable identity is SHA-256 of:

`execution_id + node_id + attempt_no + output_name`

A retry writes the same object key. If the PUT response is lost, the Adapter
uses the stable key and stored SHA-256 to recognize the completed side effect.
Reusing the identity with different content is rejected.

## Storage Namespace

Object keys use:

`tenant_id/execution_mode/workflow_family_id/v{version}/execution_id/node_id/attempt-{n}/output_name/artifact_id`

Every path segment is validated against a restricted non-secret character set.
`PRODUCTION` and `SELF_TEST` use separate namespace segments. The Domain sees
an opaque `artifact-store://` reference, never endpoint credentials.

## Output Validation

Blueprint outputs are retained in Execution IR and immutable runtime
definitions with output name, Artifact type, media type, optional schema ref,
inline schema, required flag, and optional size limits. Completion checks:

1. declared required output exists;
2. object exists;
3. media type matches;
4. schema ref and supported JSON Schema constraints match;
5. downloaded bytes, object metadata, and recorded SHA-256 agree;
6. recorded and configured size constraints match.

Failure records structured validation evidence on the failed Attempt and, when
an Artifact exists, individual checks in `artifact_validation`. The Attempt,
Node, and Execution fail; Node success is never written first.

## WHOLE_ARTIFACT Handoff

`planning-blueprint.v3` WHOLE_ARTIFACT bindings become immutable runtime
bindings. After every producer output validates, `ExecutionController` marks
the producer SUCCEEDED and evaluates pending downstream Nodes. A downstream
Node becomes READY only when every dependency is SUCCEEDED and every bound
Artifact still exists with validation PASS.

`resolve_node_inputs()` returns named `ArtifactRef` values and marks them
CONSUMED. It does not read or copy object content. FIELD_MAPPING remains
rejected at the inbound boundary.

## Persistence and API

Migration `0008_artifact_manager` extends the existing `artifact_ref`, adds
`artifact_validation`, tenant/Execution/Attempt/output uniqueness, FKs,
indexes, immutable identity and lifecycle guards, and explicit down migration.
An insert hydration trigger preserves the P0-02 legacy repository contract.

`GET /api/v1/artifacts/{artifact_id}` requires `X-Tenant-Id` and returns
metadata only. An Artifact ID from another tenant resolves as not found.

## Security and Tenant Isolation

Metadata recursively rejects password, token, API key, private key,
authorization, secret, and credential values; opaque `credential_ref` remains
allowed. Credentials are loaded from mounted secret files only inside the
composition root. All metadata operations require both tenant ID and Artifact
ID, and the database retains tenant-scoped indexes/FKs.

## Remaining Boundaries

The fake MinIO client proves SDK contract behavior without a production
dependency. Live MinIO TLS, IAM/policy, retention, and operational conformance
remain deployment verification. Schema Registry dialect remains TBD-07; the
current inline validator intentionally supports only the deterministic subset
documented by tests. P0-10 and all P1 recovery/intelligence behavior are not
implemented here.
