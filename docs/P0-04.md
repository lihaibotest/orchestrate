# P0-04 Agent Preparation and Registry Snapshot

P0-04 resolves capability requirements through `AgentRegistryPort`, then checks
each deterministic candidate through `AgentRuntimePort`: start, health,
readiness, reachability, and contract validation. A candidate failure may fall
back to the next eligible candidate. No binding or Snapshot is persisted until
every requirement has passed.

The resulting `RegistrySnapshot` and nested `AgentBinding` values are immutable.
The Snapshot freezes agent ID/version, endpoint, capability, input/output
schemas, credential reference, and invocation policy. Its SHA-256 hash uses
canonical JSON with sorted keys and requirement-sorted bindings; generated ID
and creation time are deliberately excluded. Equal family content is
idempotent, while changed content creates a new Snapshot.

Migration `0003_agent_snapshot_binding` adds binding rows, the explicit hash
algorithm, lookup index, foreign key, non-empty/object checks, and immutable
update/delete trigger. Fake Registry, Runtime, and Snapshot repository Adapters
support deterministic tests until real protocols are specified.

Run the complete gate with Python 3.10 and an isolated PostgreSQL test database:

```bash
ORCHESTRATOR_DATABASE_PATH=/tmp/p004-foundation.sqlite3 \
P0_04_PYTHON_BIN=/path/to/python3.10 \
P0_04_POSTGRES_DSN='postgresql://user:password@host/database' \
bash scripts/check-p0-04.sh
```
